# 대칭키 암호와 공개키 암호

대칭키 암호와 공개키 암호는 모두 데이터를 보호하는 데 사용되지만, 키를 사용하는 방식과 장단점이 다르다.

## 대칭키 암호

대칭키 암호는 암호화 키와 복호화 키가 같은 방식이다.

| 장점 | 단점 |
| --- | --- |
| 속도가 빠르다. | 키를 안전하게 공유해야 한다. |
| 대용량 데이터 암호화에 적합하다. | 키가 노출되면 암호문을 복호화할 수 있다. |

| 분류 | 설명 | 예시 |
| --- | --- | --- |
| 블록 암호 | 정해진 블록 단위로 암호화 | AES, DES, SEED, ARIA, LEA, HIGHT |
| 스트림 암호 | 비트 또는 바이트 흐름 단위로 암호화 | RC4 |

DES와 RC4는 현재 보안 용도로는 권장되지 않는다. 실제 사용에서는 안전한 알고리즘과 운용 모드, 키 길이, 난수 품질까지 함께 고려해야 한다.

## 공개키 암호

공개키 암호는 공개키와 개인키 한 쌍을 사용한다. 공개키는 다른 사람에게 알려줄 수 있고, 개인키는 소유자가 안전하게 보관한다.

| 장점 | 단점 |
| --- | --- |
| 키 배포 문제가 줄어든다. | 대칭키보다 느리다. |
| 암호화뿐 아니라 전자서명에도 사용된다. | 키 길이와 알고리즘 선택이 중요하다. |

| 기반 | 예시 |
| --- | --- |
| 소인수분해 문제 | RSA |
| 이산로그 문제 | ElGamal |
| 타원곡선 이산로그 문제 | ECC, ECDSA, ECDH |
| 키 교환 프로토콜 | Diffie-Hellman, ECDH |
| 전자서명 알고리즘 | DSA, ECDSA |

## 정리

- 대칭키 암호는 빠르지만 키 공유가 어렵다.
- 공개키 암호는 키 배포에 유리하지만 연산 비용이 크다.
- 실제 서비스에서는 두 방식을 함께 사용하는 [하이브리드 암호 시스템](./hybrid-encryption.md)이 많이 쓰인다.

확인한 수정 사항: DSA는 대칭키 블록 암호가 아니라 전자서명 알고리즘으로 분류한다. Diffie-Hellman은 일반적인 데이터 암호화 알고리즘이라기보다 키 교환 프로토콜로 설명하는 편이 정확하다.
